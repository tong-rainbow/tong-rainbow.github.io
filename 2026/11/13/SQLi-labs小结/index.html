SQLi-labs小结

第一步：判断注入的位置（可能的情况较多）

1.GET请求，注入点在URL(统一资源定位符）即我们所说的网址，GET请求的数据存放在请求行里

拓展：一个完整的HTTP报文从上向下由四个部分组成：请求行(Request Line)、请求头、空行、请求体（GET请求数据存放在请求头，POST请求的数据放在请求体）

“?”问号是分隔符，”&”是参数连接符（当你要传递多个参数时，用来把不同的参数隔开）

2.POST请求，注入点在请求体中（记住：请求体与请求头中间有空行隔开）

注入点可能在Username（一般），也可能是Password，下图中Username中的数据被严格处理，反而Password中的数据并未过多处理

3.注入点在User-Agent（HTTP请求中一个非常重要的请求头字段，告诉服务器我是谁，我用的是什么操作系统，什么浏览器）如下图

由下图可知，正常登陆框被严格过滤，很难进行sql注入，漏洞在于$_SERVER[‘HTTP_USER_AGENT’],后端php中使用超全局变量获取User-Agent，并且未作任何过滤直接出现在INSERT语句中（前提：需要成功登录Dumb,Dumb）

4.注入点在Referer（在请求头中，用来告诉服务器“我是从哪个网页点链接跳过来的”）

5.注入点在Cookie中（HTTP是无状态的协议，Cookie的作用相当于在登录成功之后，记住你的身份，只要登录成功之后，携带Cookie，服务器就能认出你），Username和Password被严格过滤，无法直接注入。从后端php发现setcookie，若是一开始没有Cookie就把uname设成Cookie（前提是用一个账号顺利登录），登陆之后，只要再次发送请求就会自动携带这个Cookie，这次因为你之前已经成功登录，这次$cookee=$_COOKIE[‘uname’]，没有经过任何过滤，这次用bp抓包之后就可以修改Cookie来达到注入的目的

8.堆叠注入

后端php中出现mysqli_multi_query (多重查询)，允许一次性执行用分号隔开的多条语句“；”。

知识点：mysqli_store_result 从MySQL服务器获取上一次查询产生的结果集（这里指multi_query执行的第一条查询）

mysqli_fetch_row 从传入的结果集中抓取一行数据并将内部指针向下移动一行

堆叠注入的利用

在注入点，闭合之后用分号隔开执行其他语句，update，insert，delete等等

(拓展:update 表名 set 要改的字段名=’更改的内容’ where ……定位

insert into 表名(表里的字段名，用逗号隔开) values (与字段名个数一样，一一对应要插入的数据)

delete from 表名 （where ……定位），若未定位，默认删除整张表）

绕过方法以及注入技巧

1.后端过滤注释符，方法：构造闭合,将两个引号都闭合

id=1’ and extractvalue(1,concat(0x7e,(select database()),0x7e)) and ‘1’=’1

2.后端过滤or和and，注意观察，它只进行一次全局替换，方法：双写绕过或者使用逻辑符号代替|| or && and 例如：aandnd等等

(知识点：（）括号最高优先级，算数运算符*、/、%、+、-，比较运算符=、>,等等，逻辑非NOT、！，逻辑与AND、&&，逻辑或OR、||,其他操作符)

3.看后端黑名单，注释符，and和or，空格被过滤

绕过空格的方法：()子查询,%a0(不间断空格),%0a(换行)，%09( Tab)，%0b(垂直Tab)，还有/**/(看情况使用，可以代替空格)

（在一些MySQL中可用内敛注释绕过，/*！……*/）

4.后端过滤了select,SELECT,union,UNION,Select,Union,可以通过大小写混合绕过

（/s 包含普通空格，制表符Tab，换行符，回车符）

5.后端过滤union select且不区分大小写，无法大小写混合绕过，但是它是同时过滤union空白select，可以用%a0隔开

6.宽字节注入，后端过滤引号以及反斜杠，但是设置字符集为gbk，可以使用宽字节注入来“吃掉”反斜杠，如下图，后端强制在单引号和双引号前添加反斜杠转义令引号失效。

1%df’ and extractvalue(1,concat(……))

7.参数污染whitelist只允许数字通过，java_implimentation将查询字符串按&分隔开且默认只取第一个id（因为有break），PHP的$_GET[‘id’]默认取最后一个id=，这就是漏洞所在，因为拼接进sql语句的是$_GET[‘id’]

8.order by注入，常用解法：报错注入和盲注（时间注入更常用一点）

order by注入的难点：

无法直接使用union select

无法直接使用逻辑运算符and/or

数据回显极其困难

详细方法：

?sort=extractvalue(1,concat(0x7e,(select database()),0x7e)) （无需注释，数字型）

?sort=1’,extractvalue(1,concat(0x7e,(select database()),0x7e))+–+(字符型)

若使用盲注：

注意点：如果直接?sort=1,if(…,sleep(5),sleep(0)),数据库为了搞清楚怎么排序，会对结果集中的每一行数据都执行一次（可以用来判断有多少条数据），因为ORDER BY的目的是“排序”，数据库必须为结果集中的每一行都计算出这个“排序依据”，才能对它们进行对比，ORDER BY后面接的数字不是常量而是“列序号”

一般我们正常用子查询,(select 1 from (select sleep(3))x),(select 1 from (select if(…,sleep(5),sleep(0)))x)

其中x为临时表名，因为from后面应该接表名，所有我们需要给(select sleep(5))查询结果的表命名，包装成为一个临时表

补充：sleep()函数在MySQL中的设定就是执行成功返回0，实行失败或者被中断返回1

在SQL的底层语法中，SELECT的本质并不是“查表”，而是一个“表达式求值器”，只要能算出来一个值的东西，SELECT都可以执行并把它输出

工具的使用

sqlmap是一个开源自动化SQL注入检测和利用的工具

sqlmap -u “网址” –dbs –random-agent –batch –technique等等

相关指令介绍：

–dbms=mysql（强制指定后端数据库类型）

–technique=BEUSTQ(布尔、报错、联合、堆叠、时间、带外)

-u “url”指定目标URL

-p id指定测试参数

–batch自动默认回答

–data “id=1”POST提交数据

–cookie “ ”带Cookie注入

–level 1~5 测试深度

–risk 1~3 风险等级

–dbs（所有数据库名）—D 库名

–tables（所有表名） —T 表名

–columns（所有字段名） —C 字段名

–tamper=脚本名（加载tamper脚本，用来绕过过滤、WAF、关键字拦截）

–dump（导出表里的数据也称脱库）

(1)eval()：它就像是 PHP 里的一个“黑洞”。无论你塞进去什么字符串，它都会强行把这段字符串放进 PHP 的解析器里，把它当成真正的代码去跑一遍，然后返回结果。（把字符串当代码执行），eval()并不是一个真正的函数，而是一个“语言结构”

(2)assert() 在编程中叫“断言”。它的初衷是给程序员调试代码用的。

· 语法：assert(条件表达式)
· 作用：如果条件成立（返回 True），程序继续往下走；如果条件不成立（返回 False），程序会直接报错并中断执行
在PHP7.2之前可以把字符串当成代码执行
在PHP7.2,8.0之后只是一个普通断言函数

可变函数（动态调用）—— 最优雅的绕过（确认php版本比较老）

原理：PHP 支持可变函数。如果 $a = ‘system’;，那么 $a(‘whoami’) 就等同于 system(‘whoami’)。

Payload 构造：
既然 system 被 WAF 拦截了，我们就不发 system 这个词，让它去 URL 的其他参数里找。

(3)`(反引号)

在 PHP 中，反引号是最短、最隐蔽的系统命令执行方式。
PHP 官方规定：反引号（ ` ）内的字符串，会被当作系统命令执行，并返回输出结果。它完全等价于 shell_exec() 函数。

(4)system()

system() 最大的特点就是：它不仅执行系统命令，还会把命令的完整输出（甚至是二进制数据）直接打印到网页上，最后返回命令的最后一行结果。

(5)exec()

exec()：不回显。执行命令，但只返回结果的最后一行。如果你需要完整结果，得把它存进变量里，比如 exec(‘ls’, $output); print_r($output);。

(6)shell_exec()

shell_exec()：不回显。执行命令，但把所有结果作为一个字符串返回。需要 echo shell_exec(‘ls’); 才能看到。

(7)phpinfo()

phpinfo() 是 PHP 的一个内置函数，它的唯一作用就是输出当前 PHP 环境的完整配置信息。当你访问一个包含 <?php phpinfo(); ?> 的页面时，浏览器会渲染出好几页密密麻麻的表格。

可以看到的：绝对物理路径 数据库连接信息 敏感环境变量 安全配置 版本信息 拓展信息

(8)unlink()

unlink()

· 作用：删除文件。
· 语法：unlink(string $filename, resource $context = ?): bool
· 本质：它不仅仅是在网页上隐藏文件，而是调用底层操作系统的 API，把文件从服务器硬盘上物理抹除。
$filename指相对路径或绝对路径

(9)copy()

  1. copy()

· $from：源文件路径（你要复制谁）。
· $to：目标文件路径（你要复制到哪去）。
· 返回值：成功返回 true，失败返回 false 并报 Warning。

(10)rename()

rename()

· $from：原文件路径。
· $to：新文件路径。
· 底层动作：如果原路径和目标路径在同一个分区（磁盘），它只是在文件系统的目录树里改个名字（极快）；如果在不同分区，底层会先复制文件，再删除原文件。

(11)file_put_contents()

file_put_contents()

· $filename：要写入的文件名（或路径）。
· $data：要写入的数据。可以是字符串、数组或数据流。
· $flags（关键）：
· 默认是 0：如果文件已存在，直接覆盖（清空原内容）。
· 设置为 FILE_APPEND：追加模式，在原有内容末尾继续写。
· 设置为 LOCK_EX：独占锁，防止并发写入冲突（文件锁）。
· 本质：它等价于 fopen() + fwrite() + fclose() 的连招，极其方便。

(12)fopen()/fwrite()

  1. fopen()：打开文件或 URL

语法：fopen(string $filename, string $mode)

· $filename：文件路径。它不仅能打开本地文件，还能打开 URL（如 http://…）。
· $mode：打开模式，这是核心！
· ‘r’：只读。
· ‘w’：写入（覆盖）。如果文件不存在则尝试创建；如果存在则清空内容。
· ‘a’：追加。如果文件不存在则创建；如果存在则在末尾追加，不清空。
· ‘x’：独占创建。如果文件已存在，则 fopen() 调用失败并返回 false。
2. fwrite()：向文件写入数据

语法：fwrite(resource $stream, string $data)

· $stream：fopen() 返回的文件指针。
· $data：要写入的字符串（这里可以放入恶意代码）。

3.fclose()
功能:是关闭一个已打开的文件指针，释放系统资源。在安全攻防中，fclose() 本身不是一个直接可以被利用的漏洞点（它不能执行代码，也不能直接删文件）。
例子：
$file = $_GET[‘file’];
$content = $_GET[‘content’];
$handle = fopen($file, ‘w’);
fwrite($handle, $content);
fclose($handle); // 记得关闭指针

(13)move_uploaded_file()

move_uploaded_file()

· $from：上传文件的临时路径（如 /tmp/phpXXXXXX）。通常通过 $_FILES[‘file’][‘tmp_name’] 获取。
· $to：你要移动到的目标路径（如 uploads/shell.php）。

(14)passthru()

passthru()

· $command：要执行的系统命令。
· $result_code：可选参数，用来接收命令执行后的返回状态码（0 表示成功，非 0 表示失败）。
· 核心特性：它会执行外部程序，并且直接将程序的原始输出（Raw Data）原封不动地发送到浏览器。(二进制数据)

(15)secure_file_priv：

secure_file_priv 不是一个函数，而是 MySQL 的一个全局系统变量。它的核心作用是限制通过 SQL 语句（如 LOAD_FILE()、SELECT … INTO OUTFILE）进行的文件读写操作，将数据库的文件权限“圈禁”在指定目录内。
